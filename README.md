# 翔安富文具｜官網與管理頁

## 網站功能
- 商品優先首頁、商品分類與關鍵字搜尋。
- 瀏覽器選購清單（僅本機暫存，不是正式訂單）。
- 手機版商品雙欄排列。
- 管理頁可新增、修改、刪除商品，並匯入／下載 `products.json`；每個商品規格可另填國際條碼。
- 管理頁可匯入 7-ELEVEN 賣貨便匯出的 Excel（.xlsx／.xls）或 CSV 訂單檔，先預覽欄位、手動調整欄位對應，再確認匯入。
- 以訂單編號檢查重複資料，並可匯出目前訂單清單 CSV。

## 部署到 GitHub Pages
1. 解壓縮 ZIP。
2. 開啟 `admin-config.js`，將 `window.ADMIN_PASSWORD` 改成自己的管理密碼。
3. 將所有檔案上傳至 GitHub Repository 根目錄，覆蓋同名檔案並 Commit changes。
4. 官網：`https://crowss199.github.io/SEAN0226/`
5. 管理頁：`https://crowss199.github.io/SEAN0226/admin.html`

## 賣貨便訂單匯入步驟
1. 在賣貨便後台匯出訂單 Excel 或 CSV 檔。
2. 開啟官網管理頁並登入，找到「賣貨便訂單匯入」。
3. 選擇匯出的檔案。系統會嘗試辨識欄位標題；若辨識不正確，可用下拉選單手動指定欄位。
4. 檢查預覽資料，確認「訂單編號」對應正確後，按「確認匯入訂單」。
5. 匯入後可查看訂單清單，並按「匯出訂單 CSV」備份。

## 重要限制與個資提醒
- 此功能是「下載賣貨便訂單檔，再手動上傳匯入」；不會直接連線賣貨便，也不會自動抓取新訂單。
- 訂單資料只儲存在匯入當下的瀏覽器本機儲存空間（localStorage），不會同步到其他裝置，也不會寫入 GitHub。更換瀏覽器、裝置或清除網站資料可能遺失，請定期匯出 CSV 備份。
- 訂單檔可能含有客戶姓名、電話或地址。請勿將原始訂單檔或含個資的匯出檔上傳到公開 GitHub。
- 匯入工具會嘗試辨識常見欄位名稱，但賣貨便匯出格式若有變動，請在預覽前手動調整欄位對應。建議先用少量測試檔確認欄位正確。
- Excel 讀取使用 SheetJS CDN，管理頁匯入時需有網路連線。
- 管理密碼在前端執行，原始碼可被查看；這只是簡易門檻，不是真正安全驗證。不要把管理頁視為安全的客戶資料資料庫。

## 商品更新
1. 在管理頁新增、修改或刪除商品。
2. 按「下載更新檔」取得 `products.json`。
3. 將 `products.json` 上傳至 GitHub Repository 根目錄覆蓋舊檔並 Commit changes。


## Google 試算表訂單接收設定（需完成才會正式收單）

1. 建立私人 Google 試算表「翔安富文具官網訂單」。
2. 試算表點「擴充功能 → Apps Script」，將 `GoogleAppsScript.gs` 程式貼入並儲存。
3. 執行 `setup()` 一次並授權，建立「官網訂單」工作表及出貨通知狀態欄。
4. 點「部署 → 新增部署作業 → 網頁應用程式」；執行身分選「我」，存取權選「所有人」。
5. 複製部署網址（以 `/exec` 結尾），填入 `checkout-config.js` 的 `WEB_APP_URL`。
6. 將網站檔案上傳到 GitHub Pages。

客人購物車結帳會填取件人姓名、手機、門市店號、溫層、運費與備註；商品明細自動帶入 Google 試算表。

注意：這不是賣貨便官方 API，也不會自動建立託運單。網站目前透過 Apps Script 接收資料，採 no-cors 請求，請務必檢查試算表確認是否收到。試算表必須維持私人，內含客戶個資，不可公開分享。正式收單前請先用測試資料驗證。

## 管理頁無法登入時檢查
1. 開啟 `admin-config.js`，確認 `window.ADMIN_PASSWORD = "..."` 已改成你設定的密碼，不可仍是「請改成你自己的密碼」。
2. 儲存後，將 `admin-config.js` 單獨重新上傳 GitHub Repository 根目錄並覆蓋。
3. 開啟管理頁後按 Ctrl + F5 強制重新整理，再輸入密碼。輸入時前後空白會自動去除，密碼大小寫仍須一致。
4. 若使用 GitHub Pages，等待部署更新後再試。

## 商品編號、規格與分規格庫存
- 管理頁新增商品時必須填寫唯一商品編號（例如 A001），並可新增多個規格列。
- 每個規格分別設定名稱與庫存數量；顧客在商品卡片選擇規格後，才可加入購物車。
- 購物車會依商品及規格分開計算，並在本次瀏覽器購物流程中限制不可超過設定庫存。
- 修改或刪除商品後，按「下載更新檔」下載 `products.json`，再上傳 GitHub 根目錄覆蓋舊檔。
- 舊商品匯入時會自動補上商品編號；舊商品尚未設定實際庫存，請到管理頁逐項修改規格及庫存後再發布。

**庫存同步限制：** GitHub Pages 是靜態網站。本版本的庫存數量是 `products.json` 中的展示／前端限制，顧客下單不會自動扣減雲端庫存，也無法避免多人同時購買造成超賣。若要多人即時共用庫存並在訂單成立後自動扣庫存，需要再串接具伺服器端資料庫的庫存服務。

## 商品規格與庫存無法寫入的處理
商品管理頁是 GitHub Pages 靜態網站，瀏覽器不能直接改寫 GitHub 上的 `products.json`。本修正版在新增、修改或刪除商品後不會自動下載 `products.json`；商品修改會暫存在目前瀏覽器。全部修改完成後，請手動按「下載更新檔」一次下載最新的 `products.json`。請將下載檔上傳到 GitHub Repository 根目錄並覆蓋舊檔，官網才會更新。也可使用「下載更新檔」按鈕手動下載。

## 手動寄送出貨通知

1. 客戶訂單成立後，確認「官網訂單」工作表已有該筆訂單及電子郵件。
2. 貨品實際交寄後，在 Google 試算表的「官網訂單」工作表點選該筆訂單所在的任一儲存格。
3. 點上方選單「翔安富文具 → 定位目前訂單的寄件編號欄」，在定位後的儲存格直接輸入寄件編號並按 Enter。
4. 再點選該筆訂單任一儲存格，選擇「翔安富文具 → 通知目前選取訂單已出貨」。系統會從同一列讀取寄件編號，寄送出貨通知，並記錄寄送結果。若已寄送過，系統會先詢問是否再次寄送。
5. 若選單沒有出現，請重新整理試算表；首次寄送需由試算表擁有者完成 Apps Script 郵件授權。

注意：出貨通知按鈕位於 Google 試算表上方自訂選單，不在 GitHub Pages 的網站管理頁。這是因為網站管理頁匯入的賣貨便訂單只保存在目前瀏覽器，並沒有客戶電子郵件資料可安全寄信。

## 依國際條碼同步商品庫存（V17）
1. 在商品庫存試算表下載 Excel（.xlsx／.xls）或 CSV。請確認第一個工作表有欄位標題，至少包含「國際條碼」與「庫存」兩欄；同一個國際條碼只能有一筆有效庫存。
2. 開啟官網管理頁並登入，找到「商品庫存同步（依國際條碼）」。
3. 選擇剛下載的商品庫存試算表。系統會嘗試辨識欄位；若不正確，可自行選擇國際條碼欄及庫存數量欄。
4. 檢查預覽與匹配統計後，按「套用匹配庫存至官網商品」。系統只更新有且只有一筆匹配的官網商品規格庫存；重複條碼、找不到官網條碼或非非負整數庫存都會略過。商品名稱、規格、價格及其他欄位不會更動。
5. 按「下載更新檔」下載 `products.json`，再上傳 GitHub Repository 根目錄覆蓋舊檔，官網才會顯示新庫存。

**重要限制：** 這是「試算表匯出檔 → 管理頁匯入 → 依國際條碼比對 → 發布 products.json」的半自動同步。GitHub Pages 是靜態網站，管理頁無法直接讀取私人 Google 試算表，也不能直接覆寫 GitHub 上的 `products.json`；因此必須由管理者匯出試算表並上傳，再將更新後的 `products.json` 發布。官網庫存不會即時連動或自動扣庫存。


## 訂單商品明細銷售條碼（V18）
- 結帳頁會依顧客所選規格，從 `products.json` 的 `variants[].barcode` 讀取國際條碼，連同該筆訂單商品明細送到 Google Apps Script。
- Apps Script 會建立／補齊「訂單商品明細」工作表，每個訂購規格各寫一列；「銷售條碼」欄存放該規格的國際條碼。
- 條碼以純文字寫入，保留開頭的 0；未設定國際條碼的規格會留空，不會拿商品編號代替。
- 更新時需將網站檔案上傳 GitHub，並將新版 `GoogleAppsScript.gs` 取代 Apps Script 舊程式、儲存後重新部署網頁應用程式。首次使用請執行一次 `setup()` 建立明細工作表。
- 這項功能只影響更新後新成立的訂單；舊訂單原始資料沒有送出國際條碼，無法自動回填，需另行補資料。


## V20 商品管理簡化與庫存查詢連結
- 商品管理表單不再提供「商品標籤」及「卡片文字圖案」欄位；官網商品卡片也不再顯示舊有標籤或文字圖案。既有 products.json 的舊屬性保留於資料中，編輯其他欄位時不會把它們清空。
- 「商品頁面網址（選填）」改名為「庫存查詢（選填）」。填入有效網址後，官網該商品卡片會顯示可點選的「庫存查詢 ↗」連結，另開新分頁。未填網址時不顯示連結。
- 依國際條碼同步庫存時，程式只修改匹配規格的 `variants[].stock`，並在套用後檢查商品名稱、商品編號、品牌、價格、描述、圖片、庫存查詢網址、規格名稱及國際條碼均未改變。
- 若偵測到本機舊草稿與 GitHub 最新 `products.json` 不同，會先詢問是否載入草稿，不會靜默以舊草稿覆蓋線上最新商品資料。匯入 `products.json` 也會先要求確認整份取代。
- 更新方式：網站檔案上傳 GitHub Repository 覆蓋舊檔即可，不需要更新 Google Apps Script。
